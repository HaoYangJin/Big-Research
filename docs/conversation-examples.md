# 三种模式的对话示例

三种模式使用同一个 `research-mentor` 技能。区别是 AI 从什么角度推进任务，不是三个模型或三位独立研究者。

| 你的需求 | 推荐模式 | 主要输出 |
| --- | --- | --- |
| 兴趣还很宽，不知道下一步怎么做 | 导师 `mentor` | 问题收敛、方案取舍、下一步任务与验收标准 |
| 已有论文、设计、代码或结果，需要找问题 | 审稿 `reviewer` | 按严重度排序的问题、证据位置、修复与复查方法 |
| 一边推进研究，一边检查漏洞 | 混合 `mixed` | 导师建议与审稿质疑，合并成一份行动清单 |

**阅读方式**：下面是预期行为示意，不是真实运行逐字稿，不代表已经检索文献、执行实验或保存文件。AI 只能在实际使用工具后报告这些动作完成。`用户：`之后的内容可以直接复制，再替换自己的问题和路径。

## 0. 在对话界面中调用

- **ChatGPT Work**：在输入框键入 `@`，从菜单选择已安装的 **Research Workflow**，再输入任务。仅打出 `@Research Workflow` 字符串不等于已选择插件。
- **Codex**：安装后开启新会话，用 `$research-mentor` 或自然语言明确指定技能。
- **Claude Code 插件**：先调用 `/research-workflow:research-mentor`，再输入任务。

调用入口取决于宿主。下面统一用自然语言“使用 research-mentor”，便于跨宿主阅读；先按 [快速安装](openai-install.md) 完成安装与启用。

## 1. 导师模式：把兴趣变成可以执行的问题

**用户：**

> 使用 research-mentor，导师模式。我的兴趣是智能体的长期记忆，但目前只有 CPU、Python 标准库和两小时实验预算。请帮我收敛成一个低成本可检验的问题。本轮先做问题与实验设计，不运行实验。

**AI：**

> 建议先研究一个受控问题：在固定长度的合成事件序列中，保留时间信息的检索策略能否比只按关键词检索，更准确地回答“某件事最后一次发生在什么时候”？这只验证检索机制，不证明通用智能体的长期记忆能力。
>
> 可比较无记忆、最近窗口、关键词检索、关键词加时间排序四个基线。固定事件生成规则、检索预算与测试问题，用答案准确率和检索耗时评测。
>
> 下一步先写任务定义和事前协议。验收时应能明确：什么数据、什么输入输出、哪些对照、什么结果会推翻假设。目前尚未检索文献，创新性未验证。

**用户：**

> 采用这个问题。输出目录为 `<空项目目录的绝对路径>`。先检查检索和写文件能力，再完成第一阶段，不要擅自开始后续实验。

**AI：**

> 我会先核对工具能力，在可写目录初始化项目，检索并打开相关一手来源，保存问题边界、检索记录和文献地图。工具调用后再报告实际文件、证据 ID 和检查点结果；无法访问的来源会标记为未核验。

**你检查什么**：范围是否真的收窄，方案是否符合预算，下一步是否有明确产物；“我会做”之后应有实际执行回报。

## 2. 审稿模式：检查已有实验，不替缺失证据背书

**用户：**

> 使用 research-mentor，审稿模式。我的实验把事件序列随机划分为训练和测试，只用了一个随机种子，比较关键词检索与新记忆策略。新策略准确率更高，所以我写“该方法证明了智能体拥有持续学习能力”。目前只提供这些设计信息，没有日志或结果表。请审查。

**AI：**

> **R1，主要问题：结论超过当前任务能支持的范围。** 即使准确率结果成立，检索任务也不能单独证明持续学习能力。把结论限定为此任务上的检索表现，并另行定义学习与跨任务迁移的评测。
>
> **R2，主要证据缺口：没有原始结果与协议，无法核实提升。** 需要提供逐题输出、配置、代码和执行记录；目前不能确认提升幅度或统计可靠性。
>
> **R3，需进一步检查：随机划分是否导致相关事件跨集合或未来信息泄漏。** 这是待查风险，尚不能认定已经泄漏。需要核对划分单位、记忆可见范围和测试问题生成方式。
>
> **R4，实验覆盖不足：一个种子无法评估生成器随机性。** 预先规定多种子运行和分析方法，按独立生成序列计算不确定性。
>
> 当前判断：证据不足。未看到全文，不能据此给出整篇论文评分或录用概率。

**用户：**

> 我补充了协议、代码和 CSV。请只核验 R2 和 R3，不要修改文件。

**AI：**

> 我会读取你提供的具体文件，把每个判断定位到代码、表格或协议位置。能由文件确认的问题标为“已确认”，无法排除的风险保留为“信息不足”。如果不允许或无法执行代码，会说明此次只完成静态审查。

**你检查什么**：是否按严重度排序、是否指出具体位置、是否区分已确认问题与可能风险，以及是否尊重只读范围。

## 3. 混合模式：推进实验，同时保留推翻结论的检查

**用户：**

> 使用 research-mentor，混合模式。请把“时间序列漂移下内部验证误差与未来误差的差异”推进为一个小型合成研究。只用 Python 标准库，不调用付费 API。输出目录为 `<空项目目录的绝对路径>`。先检查工具并冻结协议，再运行、写短稿、自审、修订，最后评估投稿条件。不要实际投稿。

**AI：**

> **导师视角**：先定义误差差值、对照情形和模型，冻结数据生成器、种子、指标、预算与停止规则，再执行实验并保存原始结果。
>
> **审稿人视角**：必须覆盖平稳情形和可能出现相反方向的情形；不能把合成结果外推为所有真实时间序列的规律。还要区分模型误设、分布漂移和评价协议带来的影响。
>
> **共同行动清单**：查证来源 → 保存事前协议 → 执行并记录环境与输出 → 核对数值 → 写稿 → 记录问题 ID → 修改并逐项回应 → 给出 `ready` 或 `not_ready`。两种视角共享同一份证据台账。

**用户：**

> 如果实验结果不支持原假设，也继续写完分析，不要为了得到正结果反复换种子。

**AI：**

> 保留事前规则和负结果。若要探索新的设定，会与原实验分开记录。实验是否完成、产生了哪些数值和文件，要在执行后核验；若无法运行，会记录 `blocked` 和原因。完成投稿判断时，真实数据、新颖性或外部验证不足都可能导致 `not_ready`。

**你检查什么**：是否实际产生了文件、是否保存负结果、修改是否逐项回应审查问题；同一 AI 的双视角自审不能替代独立同行评审。

## 4. 对话中切换模式与恢复

**用户：**

> 切换到审稿模式，只审查当前实验设计，不再继续执行。

**AI：**

> 本轮按最新明确指令采用审稿模式，聚焦实验设计并停止推进执行。

v1.0.0 的对话指令可以切换行为模式，但 CLI 没有更新项目 `mode` 的专用命令；`project.json` 可能仍显示初始化模式。读取状态时应区分这两个含义，详见 [缺陷与限制](limitations-v1.0.0.md)。

**用户：**

> 继续项目 `<原项目目录的绝对路径>`。混合模式，先检查保存状态和现有产物，从中断位置继续，不重新初始化。

**AI：**

> 我会先读取项目与证据台账并运行状态校验；发现已记录文件变化时，先定位最早受影响阶段，再用 `reopen` 复核下游。没有可访问的持久目录时，会说明此次不能直接恢复文件状态。
